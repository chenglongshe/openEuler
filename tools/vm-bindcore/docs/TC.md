# TC（Test Case，测试用例）

---

> 以下测试用例均从**最终用户（虚拟化平台管理员）可执行、可观测**的角度编写，覆盖 SR 和 US 的核心验收场景。

---

## TC-01：虚拟机创建 — 端到端验证

| 项目 | 内容 |
|------|------|
| **关联** | SR 场景 1, US-01 AC-US-01-01 |
| **前置条件** | 宿主机系统正常运行，存储和网络资源充足，节点代理服务已启动 |

**步骤**：
1. 管理员调用创建虚拟机 API，指定参数：2 vCPU、4 GB 内存、40 GB 系统盘、连接端口组 `pg-vlan100`
2. 等待创建完成后，在宿主机上执行 `virsh list --all`
3. 在宿主机上执行 `ps aux | grep qemu`

**预期结果**：
- 步骤 2：`virsh list --all` 输出中 **可看到** 新建的虚拟机名称，状态为 `running`
- 步骤 3：`ps aux` 输出中 **可看到** 对应的 QEMU 进程正在运行

---

## TC-02：虚拟机删除 — 进程清理验证

| 项目 | 内容 |
|------|------|
| **关联** | SR 场景 2, US-01 AC-US-01-02 |
| **前置条件** | 承接 TC-01，虚拟机已创建且处于运行状态 |

**步骤**：
1. 记录待删除虚拟机的名称和对应的 QEMU 进程 PID
2. 管理员调用删除虚拟机 API
3. 等待删除完成后，在宿主机上执行 `virsh list --all`
4. 在宿主机上执行 `ps aux | grep qemu`

**预期结果**：
- 步骤 3：`virsh list --all` 输出中 **看不到** 被删除的虚拟机
- 步骤 4：`ps aux` 输出中 **看不到** 该虚拟机对应的 QEMU 进程

---

## TC-03：虚拟机快照创建与恢复

| 项目 | 内容 |
|------|------|
| **关联** | US-02 AC-US-02-01, AC-US-02-02 |
| **前置条件** | 虚拟机 vm1 处于运行状态，存储空间充足 |

**步骤**：
1. 管理员调用快照创建 API，为 vm1 创建快照 `snap-01`
2. 在宿主机上执行 `virsh snapshot-list vm1`
3. 管理员登录 vm1，在 Guest 内创建测试文件 `/tmp/test-after-snap`
4. 管理员调用快照恢复 API，恢复 vm1 到 `snap-01`
5. 管理员登录 vm1，检查 `/tmp/test-after-snap` 是否存在

**预期结果**：
- 步骤 2：快照列表中 **可看到** `snap-01`
- 步骤 5：文件 `/tmp/test-after-snap` **不存在**，说明系统状态已回退到快照创建时的状态

## TC-04：虚拟交换机与端口组 VLAN 配置变更

| 项目 | 内容 |
|------|------|
| **关联** | SR 场景 3, US-03 AC-US-03-01, AC-US-03-02 |
| **前置条件** | Open vSwitch 已安装并运行，节点代理服务已启动 |

**步骤**：
1. 管理员调用 API 创建虚拟交换机 `vswitch-01`
2. 在宿主机上执行 `ovs-vsctl show`，确认交换机已创建
3. 管理员调用 API 创建端口组 `pg-vlan100`，设置 VLAN ID = 100
4. 管理员调用 API 将端口组 `pg-vlan100` 的 VLAN ID 修改为 200
5. 管理员通过查询接口查看端口组 `pg-vlan100` 的当前 VLAN 配置

**预期结果**：
- 步骤 2：`ovs-vsctl show` 输出中 **可看到** `vswitch-01` 已存在
- 步骤 5：查询结果中 **可看到** 端口组 `pg-vlan100` 的 VLAN ID 已变更为 200

## TC-05：存储资源创建、扩容与删除

| 项目 | 内容 |
|------|------|
| **关联** | SR 场景 4, US-04 AC-US-04-01, AC-US-04-02 |
| **前置条件** | 系统存储后端正常，节点代理服务已启动 |

**步骤**：
1. 管理员调用 API 创建 100 GB 的数据存储 `ds-01`
2. 管理员通过容量查询 API 查看 `ds-01` 的容量
3. 管理员调用扩容 API 将 `ds-01` 扩容到 200 GB
4. 管理员通过容量查询 API 再次查看 `ds-01` 的容量
5. 管理员调用删除 API 删除 `ds-01`
6. 管理员通过查询 API 查看存储列表

**预期结果**：
- 步骤 2：**可看到** `ds-01` 总容量为 100 GB
- 步骤 4：**可看到** `ds-01` 总容量已变为 200 GB
- 步骤 6：存储列表中 **看不到** `ds-01`

## TC-06：虚拟机生命周期操作（启动/停止/重启）

| 项目 | 内容 |
|------|------|
| **关联** | US-01 |
| **前置条件** | 虚拟机 vm1 已创建并处于运行状态 |

**步骤**：
1. 管理员调用停止虚拟机 API 停止 vm1
2. 在宿主机上执行 `virsh list --all`，确认 vm1 状态
3. 管理员调用启动虚拟机 API 启动 vm1
4. 在宿主机上执行 `virsh list --all`，确认 vm1 状态
5. 管理员调用重启虚拟机 API 重启 vm1
6. 等待重启完成后，在宿主机上执行 `virsh list --all`

**预期结果**：
- 步骤 2：vm1 状态为 `shut off`（已关闭）
- 步骤 4：vm1 状态为 `running`（运行中）
- 步骤 6：vm1 状态为 `running`（运行中），虚拟机重启成功
